Sigil agents can fully manage SPL (Solana Program Library) tokens through the built-in tool registry. All operations execute on **Solana Devnet**.

## Available Tools

| Tool | Description |
|---|---|
| `create_token` | Create a new SPL token mint |
| `mint_tokens` | Mint tokens to a recipient (requires mint authority) |
| `burn_tokens` | Burn tokens from the agent's wallet |
| `get_token_accounts` | List all associated token accounts |
| `create_token_account` | Initialize a token account for a specific mint |
| `close_token_account` | Close an empty account and reclaim rent |
| `set_token_authority` | Transfer mint or freeze authority |

## Example Directives

These directives leverage the SPL token tools:

```text
"If a token account has zero balance, close it and reclaim rent"
"Mint 100 DEMO tokens every day at 9am"
"If I create a new token, mint 1,000,000 to my primary wallet"
"Burn any SPAM tokens that appear in my wallet"
```

## Token Lifecycle

A typical token workflow:

1. **Create** a new token mint with `create_token`
2. **Create** associated token accounts for recipients with `create_token_account`
3. **Mint** initial supply with `mint_tokens`
4. **Transfer** tokens between wallets (see DeFi tools)
5. **Burn** unwanted tokens with `burn_tokens`
6. **Close** empty accounts to reclaim rent with `close_token_account`

## Guardrail Integration

All token operations pass through the Guardrails layer:

- `mint_tokens` — Checked against daily volume limits
- `burn_tokens` — Checked against per-trade value limits
- `close_token_account` — Always allowed (reclaiming rent is never risky)
- `set_token_authority` — Requires explicit allowlist approval

See [Safety & Guardrails](/docs/guardrails/safety) for details.
