# The Sigil Browser Extension

The Sigil Browser Extension acts as a bridge between standard web applications (dApps) and your local AI Agent. 
It injects the `window.sigil` provider into standard web pages, which acts as a Solana Wallet Adapter.

When a dApp requests a signature, the Extension intercepts the transaction and forwards it to your local Sigil instance. Sigil decodes the transaction, passes it through your configured **Guardrails**, and uses its LLM reasoning capabilities to assess the risk of the transaction, presenting a detailed analysis back to you before you approve the action.

## Installation Guide (Developer Mode)

Because the extension is still in development, it is not yet available on the Chrome Web Store. You must install it locally.

### 1. Download the Extension

[Download the latest Extension build (`.zip`)](/sigil-extension.zip)

*(Note: We will host the zip file here shortly. If you are building from source, see below).*

### 2. Install in Chrome or Brave

1. Open a new tab and navigate to `chrome://extensions/`
2. At the top right, toggle **Developer mode** ON.
3. Click **Load unpacked** in the top left corner.
4. Select the unzipped directory containing the `manifest.json` file.
5. The Sigil Extension will now appear in your list of extensions.

### 3. Connect!

With the extension installed and your local `sigil` daemon running (e.g. `sigil start`), you can now connect to dApps.

## How it works

1. **dApp Request**: A dApp (like Jupiter or MagicEden) calls `window.sigil.signTransaction(tx)`.
2. **Simulation**: The extension grabs this Transaction buffer and sends it to `localhost:74445/api/extension/simulate`.
3. **Agent Analysis**: Your active Sigil agent breaks down the instructions. If it triggers an immediate Kill Switch or Guardrail failure, it's blocked instantly. 
4. **LLM Evaluation**: If Guardrails pass but the size/risk requires confirmation, the LLM generates a human-readable threat analysis.
5. **Approval**: You review the result. Once you click Approve, Sigil decrypts your local key using `keytar`, signs the transaction, and returns the signed buffer to the dApp. Private keys NEVER leave your OS Keychain.
